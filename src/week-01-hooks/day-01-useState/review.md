# Day 01 — useState 회고

미니 장바구니 (담기 / 수량 조절 / 파생 계산 / localStorage / 재고 상한)

## 배운 것 3가지

1. **파생 가능한 값은 상태로 두지 않는다.** 총 수량·총 금액·항목별 소계는 `items`만 있으면 계산되는 값이라 `useState`로 관리하지 않고 렌더 본문에서 매번 계산한다. 파생값을 상태로 들면 원본과 동기화하는 코드가 생기고 거기서 버그가 난다.
2. **다음 상태가 이전 상태에 의존하면 함수형 업데이트를 쓴다.** `setItems(prev => ...)` 에 넘긴 함수는 "예약된 시점 기준 최신 state"를 받는다. 한 이벤트에서 여러 번 갱신하거나 비동기 콜백에서 갱신할 때, 렌더 클로저에 갇힌 낡은 값이 아니라 최신 값으로 계산된다. (리렌더를 예약하는 건 setter 호출 자체이고, 함수형이든 값이든 동일하다 — 함수형의 이점은 "정확성"이지 "렌더 알림"이 아니다.)
3. **최소 상태 + 렌더 시 조합.** 장바구니는 `{ id, quantity }[]` 만 들고, 이름·가격·재고는 `PRODUCTS`에서 `id`로 찾아 `lines` 라는 파생 배열을 만들어 화면에 그린다. 상품 데이터를 상태에 복사하지 않는다.

## 막혔던 지점 / 헷갈린 것

- **상태 설계를 먼저 안 하고 개발을 시작해서** 1차 코드가 지저분했다. 항목에 `totalPrice`, `possibleStock`(재고 상한)까지 복사해 들고 있었고, 그 결과 수량 변경 시 단가를 나눗셈으로 역산하는 취약한 코드(`totalPrice + totalPrice / quantity`)가 나왔다.
- **게으른 초기화 문법을 흉내만 냈다.** `useState(loadCart())` 로 호출해서 매 렌더마다 localStorage를 읽고 파싱하고 결과를 버리고 있었다. `useState(loadCart)` 처럼 **함수 참조**를 넘겨야 첫 렌더에만 실행된다.
- **정규화를 어렵게 생각했다.** `{ id, quantity }` 만 들고 나머지를 `PRODUCTS`에서 참조하는 게 이미 정규화다. 도전 과제의 `Record<id, quantity>` 는 같은 원칙에 자료구조만 다른 것(O(1) 조회, 중복 불가).
- **재고 상한을 UI에서만 막았다.** `disabled={quantity >= stock}` 는 UX용이고, "수량 ≤ 재고" 라는 불변식은 `changeQty` / `addToCart` 안에서도 강제해야 한다. 그 함수는 버튼 외의 경로(테스트, 다른 기능)에서도 불릴 수 있다. → `Math.min(next, stock)` 한 줄.
- **테스트에서 과하게 계산하려 했다.** "총 금액이 맞는지"를 검증하려고 가격 태그들을 찾아 합을 구해 비교하려 했다. 실제로는 **알려진 입력을 넣고**(아메리카노 x2 + 카페라떼 x1) **기대값을 하드코딩**해서(`총 금액: 14000원`) 화면에 그 텍스트가 있는지 보면 된다.

## 스스로 내린 설계 결정과 근거

- **상태 구조:** `Cart` 컴포넌트 내부에서 "장바구니에 담긴 항목"만 `useState<CartItem[]>` 로 관리. `CartItem = { id, quantity }`. 나머지는 전부 `PRODUCTS` 에서 파생. 새로고침 유지를 위해 `useEffect` 로 `items` 를 localStorage 에 동기화.
- **함수형 업데이트를 쓴 이유:** `addToCart` / `changeQty` 모두 "기존 배열 → 새 배열" 이라 이전 상태에 의존한다. 낡은 클로저 값이 아닌 최신 값 위에서 `map` / `filter` 하기 위해.
- **파생 상태 처리:** `PRODUCTS` 에서 얻을 수 있는 값(이름·단가·재고)은 상태에 넣지 않고, 필요할 때 `id` 로 찾아 조합. 총계류는 렌더 본문에서 `reduce`.
- **localStorage 는 side effect 로 취급:** 파생값을 `useEffect` 로 미러링하는 건 안티패턴이지만, 외부 시스템(localStorage)과의 동기화는 `useEffect` 가 맞는 자리. (Day 8 에서 `useLocalStorageState` 커스텀 훅으로 분리 예정)

## 리뷰에서 지적받은 것

- `key` 대신 `id={...}` DOM 속성을 썼음 → `key={...}` 로
- 변수 섀도잉 (`items.map((items) => ...)`) → `line` 등으로
- `useMemo` 를 총액 계산에 미리 씀 → Day 3 주제, 지금은 작은 배열이라 이득 없음. 렌더 본문 계산으로 통일
- "제거됨" 검증은 `총 수량: 0` 이 아니라 항목/버튼이 사라졌는지(`queryBy...().not.toBeInTheDocument()`)로 — 전자는 `.filter` 를 지워도 통과하는 약한 테스트
